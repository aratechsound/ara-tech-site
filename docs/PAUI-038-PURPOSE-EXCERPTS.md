# PAUI-038 local purpose excerpts

Exact parent: PAUI-036 bafc3742db4f49bb19b103aeda8932960c616d24. PAUI-037 provider, API transport, billing and durable-cache code are not adopted. Publication is forbidden for this task.

The original extractor recognizes a limited set of entire greeting/introduction lines, stops at the first unrecognized line and then returns only the next three physical lines. Variants such as 平素より大変お世話になっております, formal self-introductions and folded addressees can therefore consume all three lines. Wrapping and introductory background can also consume the prefix before a late request. The saved preview previously preferred snippet over available body_html; this is a separate source-priority defect. If only a snippet or a previously capped body exists, extraction cannot recover missing text.

The deterministic local extractor matches normalized copies of unambiguous boilerplate but returns original source spelling and punctuation. It preserves accepted short/good prefixes when no specific matters occur later. For long mail it groups contiguous sentences, paragraphs, wrapped text and bullets; attaches an immediately following proviso/uncertainty to its context; scores requests/questions/changes and concrete numbers/dates/amounts/deadlines; selects up to three complete source units and restores their source order. Only internal wrapping whitespace is folded. It never paraphrases, creates facts, infers obligations, or cuts through a selected sentence or number. Ambiguous text and greeting-only messages fall back to original excerpts rather than fabricated intent. Unmarked signatures remain when uncertain; unambiguous signature and quote markers end the new-message section.

This is a lexical ranking of original passages, not semantic AI or a guarantee of exhaustive coverage. A very long sentence may wrap beyond three visual rows, and the existing three-row CSS preview can clip it, especially on narrow screens; the normal full-body action remains available. An unknown formulation can use conservative original-text fallback. Three selected source units are the logical limit, not a claim that every important matter in arbitrary mail has been understood.

savedExcerpt now prefers body_text, then inert HTML-to-text, then snippet. The existing body/full-quote reader is unchanged in how it fetches, binds and opens originals. A small label distinguishes 用件抜粋 from 原文 and clearly marks snippet-only/body-not-retrieved states. HTML scripts, remote media and other active elements are never mounted. Normal body reads remain lazy, concurrency-limited and session-cached; no new network request or database state is added.

Scope is mail-purpose.mjs, one source-priority line in mail-model.mjs, source labels in mail-body-view.mjs, fictional regression fixtures/tests and this design note. Backend/API/ACL/Gmail normalization, deliveryUnknown, fullBody, attachments, directions, timestamps and case identity remain unchanged. The legacy upstream body normalizer's 50,000-character cap and HTML-preview cap remain existing source limitations, separately reported rather than presented as recovered full text.

Fictional A-N tests cover greeting variants, long addressee/self-introduction, accepted good prefix, bullets and quantities, multiple questions, money/deadline, negation/cancellation/uncertainty, long quoted history, inert HTML, short acknowledgements, signatures, snippet-only state, greeting-only fallback and late requests behind wrapped/background text. The actual desk tests cover original expansion, quote opening, delayed snippet body reads and case switching, with no business writes or external AI. Existing tests are retained without skip or expectation relaxation. Production acceptance remains a separate task.
