# 開催予定・実績の運用

短い自然言語指示から公式情報調査・管理画面の「公開待ち」登録まで進めるCodex運用は、`UPCOMING_EVENT_CODEX_WORKFLOW.md` を参照してください。公開待ちは認証済み管理画面だけで確認でき、代表が「公開する」を明示実行するまで一般公開されません。

## 公開前の必須確認

- 会場または主催者の公式Webサイトで、対象公演が一般公開されていることを人間が確認する。
- 公演名、開催日、会場、地域、ARA-TECHの担当予定、公式告知URL、告知解禁確認日を確認する。
- ARA-TECHが主催者でない場合、主催者であるような表現を使わない。
- フライヤーは利用権を確認できた場合だけアップロードする。外部サイトからダウンロードして再ホストしない。画像なしでも公開できる。
- Google Event構造化データを出すには、会場の詳細住所も入力する。

## 新しい開催予定を掲載する

1. `admin.html` に管理者としてログインし、「公開待ち」を開く。
2. 候補の確認用フライヤー、公式情報元、画像利用状態を確認する。
3. 「プレビュー」で実ページ相当の表示を確認し、必要なら編集して保存する。
4. 画像利用確認済みの場合だけ公開画像をアップロードして「公開ページで画像を使用」をONにする。
5. 人間による最終確認後に「公開する」を押し、確認ダイアログに同意する。

開催予定の公開には、アーティスト名またはイベント名、未来または当日の開催日、会場、地域、ARA-TECHの担当内容、HTTPSの公式告知URL、告知解禁確認日が必要です。自動スクレイピング、自動判定、自動公開は行いません。

## 開催後の実績表示

公開表示はAsia/Tokyo基準で開催日を判定し、開催日の翌日00:00から自動的に実績へ切り替わります。DBの状態を定期更新するcronは使用しません。日付未設定または不正な日付は既存の状態を保持し、安全側で自動変更しません。

1. 紹介文や担当内容など実績固有の情報を追記する場合だけ、登録済みの投稿を編集する。新規投稿は作成しない。
2. 公開URL（slug）は変更しない。
3. 必要に応じて状態を「終了済み（実績）」へ変更し、機材・システム構成、利用権を確認済みの画像を追加する。
4. 保存後、同じ `/works/{slug}.html` が実績タイトル、実績説明、実績表示になっていることを確認する。

## SEOと構造化データ

- 開催予定と終了済みで、title、description、OGP、表示ラベルを切り替える。
- canonicalは状態変更前後で同一の個別URLを維持する。
- 公開済みの個別URLは動的sitemapに含まれる。
- Event構造化データは、開催予定かつ日付、会場、地域、詳細住所、公式告知URLが揃った個別ページだけに出す。
- 画像がない場合はEvent画像を出さない。
- Googleの表示は保証されない。公開後はRich Results TestとSearch Consoleで別途確認する。

仕様確認先: https://developers.google.com/search/docs/appearance/structured-data/event
